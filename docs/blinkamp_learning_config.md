# 当前 BlinkAMP 学习参数

> 当前已按用户要求切换至原版每轮学习预算重跑，详见 [原版预算实验](blinkamp_original_budget.md)。
> 下文先前512环境配置及结果保留作历史对照；当前正式队列为 `original_budget_suite_mlp`。


本配置整理对应 `dinosaur_physhsi_suite` 的 seed 0/1，依据实际 `args_resume.json`、优化代码和检查点，而非 TrainConfig 的历史默认值。此次仅整理配置，未改变训练参数。

**训练和采样**

| 项目 | 生效值 | 含义 |
|---|---:|---|
| 训练预算 | 每种子 200,000 iteration | 前 500 iteration 冻结策略校准 |
| 并行环境 | 512 | 控制频率 50 Hz，dt=0.02 s |
| 每轮采集 | 4 步/环境 | 每轮 2,048 条真实转移 |
| 状态回放容量 | 256 步/环境 | 合计 131,072 条，单环境覆盖 5.12 s |
| 世界模型留出环境 | 32 / 512 | 不参与世界模型优化批次；策略起点可采样全部环境 |
| 启动回放填充 | 64 步/环境 | 32,768 条；warm resume 时重新填充 |
| Actor 历史 | 6 帧 | 状态观测归一化后拼接 |
| 想象长度 | 16 步 | 0.32 s，末端 Critic bootstrap |
| 策略起点 batch | 512 | 每轮形成 8,192 条想象转移 |
| 折扣 gamma | 0.99 | 16 步末端折扣约 0.851；长期价值依赖 Critic |
| Critic lambda | 0.95 | 用于 Critic 的 lambda-return；Actor 用可微想象回报 |
| 探索 | 独立高斯噪声 std=0.1 | 加在真实采集动作上，再裁剪到 ±3 |
| Actor EMA | 0.995 | 默认最终评估用 EMA；半衰期约 138 次 Actor 更新 |

200k iteration 约对应 4.096 亿条真实采集转移，另有启动/恢复时的回放填充。样本重复使用、并行环境和窗口重叠意味着该数字不是独立轨迹数量。

**每个 iteration 的更新预算**

| 模块 | Adam 学习率 | 更新次数/轮 | 单次训练样本 | 网络隐藏层 |
|---|---:|---:|---|---|
| Actor | 2e-4 | 1 | 512 起点 × 16 步想象 | 512, 256, 128（ELU） |
| Critic | 4e-4 | 3 | 同一批 8,192 个想象状态及固定目标 | 256, 128（ELU） |
| 世界模型 | 4e-4 | 5 | 1,024 个窗口 × 4 步 | 1024, 1024, 1024（SiLU + LayerNorm） |
| 力矩预测头 | 4e-4 | 5 | 对应世界模型窗口的真实力矩标签 | 256, 256（SiLU），输出 58 维 |
| AMP 判别器 | 1e-4 | 2 | 512 专家窗口 + 512 真实策略窗口 | 512, 256（ReLU） |

所有模块使用 Adam，betas=(0.9,0.999)、eps=1e-8、weight_decay=0，学习率固定，无 scheduler。每次优化使用全局梯度范数上限 1.0；日志中的 actor_gradnorm 是裁剪前范数。Actor 更新期间冻结世界模型、力矩头、判别器和 Critic 的参数，但保留它们对输入的梯度。

一轮合计 16 次 optimizer step：Actor 1、Critic 3、世界模型 5、力矩头 5、判别器 2。世界模型每轮抽取 5,120 个四步窗口、合计 20,480 个时间位置，约为新采集真实转移数的 10 倍；这只是抽样量比例，不是 10 倍独立数据。半批世界模型数据做左右镜像。reset 后窗口通过 mask 截断。

**模型损失与预热**

- 世界模型：结构化动力学，4 步自回归预测，按状态增量标准差归一化后的 MSE，并设置误差尺度下限。训练窗口仅 0.08 s；策略在模型内展开 0.32 s，长于监督窗口。
- 力矩头：实际力矩和未限幅需求分别除以各关节力矩上限后计算 MSE，两项相加。实际力矩输出用 tanh 限幅，需求输出不限幅。
- 判别器：最小二乘分类（专家 +1、策略 −1），专家输入梯度惩罚系数 0.5。
- Actor：最大化带可微存活概率、折扣和末端价值的想象回报；没有 PPO clip、熵奖励或学习到的动作方差。
- Critic：对固定 lambda-return 目标做 3 次 MSE 优化；没有独立 target Critic。
- 世界模型预热阈值 100、力矩预热阈值 500，实际策略从第 501 iteration 开始更新。校准阶段判别器也训练，Actor 保持冻结。
- 只继承旧实验的世界模型权重及其归一化 buffer；其他模块每种子重新初始化。随后从各自 500 iteration 校准检查点恢复全部模块和优化器。

**AMP 和任务设置**

| 项目 | 生效值 |
|---|---|
| AMP 窗口 | 10 帧 × 每帧 57 维，输入 570 维；五点包含 head 对应 mid360_link |
| 判别器输入归一化 | 关闭，使用原始特征 |
| 负样本池 | 32,768 个真实策略窗口；半批从最近至多 4,096 个窗口采样，半批从全池采样 |
| AMP reward | max(0, 1 − 0.25 × (D−1)²) |
| 最终奖励 | 0.7 × 环境奖励 + 0.3 × 0.5 × AMP reward |
| 环境奖励 dt | 九项源奖励求和后乘 0.02；AMP 部分不再乘 dt |
| 动作库 | Dinosaur FW/BW/SW 等权，原始 60 Hz，分数帧插值，批次共享 0.9–1.1 时间缩放 |
| 指令 | vx/vy 各 ±0.8 m/s，yaw ±0.5 rad/s；源 0.2 死区，每 8 s 重采样 |
| 参考初始化概率 | 0.5 |
| 初始根速度 | 参考 ±0.2、默认 ±0.5，仅初始化时采样 |
| episode | 15 s，源超时判据 >750 步 |
| 扰动与噪声 | episode 内无外力/速度 kick；观测噪声沿用 BlinkMimic |

源任务 profile 下，`stand_fraction=0` 不表示完全没有停止指令：源死区仍可生成零指令；`command_max=0.8` 也不是唯一控制命令范围的参数，实际各轴范围来自源任务分支。

**归一化的实际状态**

RunningNorm 在累计计数达到 2e8 后冻结。检查点显示：

- 首个 Dinosaur 校准结束时，世界模型 in/out/inc_norm 的 count 已均为 200,003,584；这些统计来自继承的世界模型，进入本轮 Dinosaur 训练时已经冻结。
- seed 0 的 200k 检查点中，Actor norm count=200,000,000，Critic norm count=200,000,512，均已冻结。
- Actor 正常每轮计数增加 2,048，约在总训练 97.6k 附近冻结；Critic 每次 Actor 更新计入 8,704 个状态，约在 23.5k 附近冻结（具体受启动/恢复影响）。

因此，本轮并非所有输入/输出统计都始终随 Dinosaur 数据更新。继承冻结统计是否拖慢适应值得做独立对照，但现有结果不能证明它就是主要瓶颈。

**实测速度及需要关注的限制**

seed 0 最后 10k iteration 平均 8.22 it/s，相当于约 16.8k 真实转移/s、67.3k 想象时间位置/s；后者不等于独立测量的模型纯推理吞吐。200k 总训练计时约 6.75 小时。seed 1 本次读取时为 28.4k，最近 100 条日志均值约 8.52 it/s。

seed 0 最后 10k 的 Actor 裁剪前梯度范数均值约 3.18，高于裁剪阈值 1.0；均值本身不能给出裁剪发生率，但提示应统计实际裁剪比例。相同区间真实 AMP 奖励为零的窗口比例均值约 6.23%，这些窗口在 reward clamp 的平坦区不能提供 AMP 输入梯度，其他任务奖励仍可能提供梯度。

从参数配置看，优先值得对照的因素是：短想象长度与末端价值依赖、每轮仅一次策略更新且使用固定 2e-4 学习率、梯度裁剪强度、世界模型监督/策略展开长度差异，以及继承的冻结归一化统计。它们分别影响规划范围、更新预算、更新幅度和模型适应，尚不能仅凭配置认定因果。判别器损失/奖励曲线和模型预测误差也应一并检查。当前未做阶段耗时 profiling，因此不能把计算耗时准确归因于某个模块。

配置来源：`logs/blinkamp/dinosaur_physhsi_suite/seed0_200k/args_resume.json`；实现：`src/blinkamp/learning.py`、`src/blinkamp/amp.py`、`src/blinkamp/torque.py`、`src/blinkmimic/networks.py`。本配置清单不改变已经对齐的奖励、动作和初始化设置。

**与原版 BlinkMimic 发布配方的核对**

对照的是 `scripts/presets.sh` 的 `main` 以及本机成功复现的 `logs/reproduce_local/s0/args.json`，不是仅比较 train.py 默认值。结论：沿用了核心世界模型训练思路，但当前 BlinkAMP 的学习参数没有完整对齐发布配方。

| 项目 | 原版 main / 本机成功复现 | 当前 BlinkAMP |
|---|---|---|
| 并行环境 | 4,096 | 512 |
| 每轮采集 | 平均 2.5 个向量步（UTD=0.4） | 4 个向量步（等效 UTD=0.25） |
| 新真实转移/轮 | 平均 10,240 | 2,048 |
| 回放容量 | 1,000 × 4,096 = 4,096,000 | 256 × 512 = 131,072 |
| 想象 horizon | 32 步，0.64 s | 16 步，0.32 s |
| Actor batch | 2,048 起点，65,536 想象时间位置 | 512 起点，8,192 想象时间位置 |
| Actor 更新/轮 | 1 | 1 |
| 世界模型 batch × window | 2,048 × 8 | 1,024 × 4 |
| 世界模型更新/轮 | 5 | 5 |
| Actor/WM 优化器 | MuonAdam 混合优化 | 全部 Adam |
| 基础 LR | 4e-4，有余弦衰减 | WM/Critic/力矩 4e-4，固定 |
| Actor LR | 初期约 1.6e-3，触发后倍率从 4 降至 1，约 4e-4；另有基础余弦调度 | 固定 2e-4 |
| Critic | 5 epochs × 4 minibatches = 20 次优化 | 3 次全批优化 |
| Actor 历史 | 10 帧 | 6 帧 |
| Actor 网络 | motion encoder 和 decoder 各 2048/1024/512/256，参考动作残差连接 | 指令编码器 64/64→32，Actor 512/256/128，无参考动作残差 |
| 策略预热 | main 的 wm_only_iters=0 | 冻结至 500 iteration，用于新增力矩头校准 |
| 实现加速 | bf16 MLP、CUDA Graph、采集 Graph、异步轻量检查点等 | FP32/TF32，局部 torch.compile、fused Adam，同步完整检查点 |

一致项包括 gamma=0.99、lambda=0.95、真实动作探索 std=0.1、EMA=0.995、启动采样 64 步、WM 隐藏层 1024×3、结构化动力学、WM 半批镜像、梯度范数上限 1.0 及 Critic 隐藏层 256/128。原版还追加 Actor 逐元素梯度裁剪 ±0.1，BlinkAMP 没有追加该项。RunningNorm 的 2e8 冻结机制也是共享机制，差异是 BlinkAMP 导入了已经冻结的统计。

当前每轮想象时间位置为原版的 1/8，世界模型监督抽样时间位置为 1/4。不过新真实采样也为原版的 1/5，不能仅凭每轮 batch 比较样本效率：想象时间位置/新真实转移的比例为原版 6.4、当前 4.0。两者 iteration 不是等量工作单位，直接拿 3500 与 200k iteration 比较收敛速度并不公平。

上述预算、优化器、LR 和网络缩小属于 BlinkAMP 实现时的配置选择，并非奖励/motion 对齐 PhysHSI 的必需变更。AMP 判别器与力矩头是新增训练负担；原版还有参考未来目标、参考动作残差及困难片段采样等监督优势，因此即使统一数值超参数，也不能保证复现相同学习速度。这里未改变在训实验。
